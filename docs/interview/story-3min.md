# 3 分钟项目介绍（骨架 v1，双结局版）

> 用法：背结构不背稿。〔槽位〕处等实验 0 结果填入；两种结局共用前 80% 内容。
> 配套：数字弹药库（numbers-bank.md）、20 问题库（questions-20.md）。

## 0:00–0:15 定位（ hook ）

"我做的是 LLM 推理系统的 KV cache 分层存储——把 HPC 内存层级优化的方法迁移到
SGLang 的 HiCache 子系统：GPU HBM、host DRAM、SSD 三层之间的前缀缓存回载。
核心产出是一套可审计的因果实验方法，和它定位出的〔真 bug/修复验证〕。"

## 0:15–1:00 问题与方法（为什么难、我怎么做的）

"这个领域最大的坑是结论不可信：三个月里上游 mem_cache 就有 660 多个提交，配置
漂移能让同一个实验的结论完全翻面。所以我先建了锚定基础设施——40 位 commit 锚定、
模型 sha256 校验、结果包审计器，负结果也原样留档。

在这之上我用消融矩阵拿到了基线数据：kernel IO 后端的 L2 回载比冷 prefill 快
2.7 倍（配对中位比 0.375）、FP8 KV 让容量翻倍只损失 4% 回载效率、关 CUDA graph
劣化 11%——这些数字划定了机制讨论的边界。"

## 1:00–2:15 机制深挖（展示技术深度的高潮段）

"然后是我最得意的一个排查：L3 存储后端命中率归零的负结果。表面看像存储丢了数据，
我做了双臂对照实验证明是两层机制叠加：第一层，prefetch 插入 host 树时用的是
anchor 根节点的空命名空间，带 salt 的请求重匹配看不到它——去掉 salt 后命中立即
恢复，因果成立；第二层，prefetch 暂存和异步写回竞争同一个 host 池，水位常年 100%，
凑不够 256 token 阈值就被静默撤销。

这个负结果在两台不同机器上复现过，说明是架构性的。我顺着查了上游 main 的修复：
salt 归属已经修了，staging 改成了'查询零占用、命中才分配'——但这两个修复都没有
独立的验证证据，而且我在代码里找到了饥饿仍可能发生的通路：写暂存的 protect_host
钉住语义没变，admission 排队期间的页依然没有防逐引用。"

## 2:15–2:45 结局（二选一）

**结局 A（实验 0 发现仍复现）——实际发生，2026-11-21 实测**：
"于是我在 main 上跑了双臂验证：salt 归属确实修好了——salted 和 saltless 臂命中
完全一致（各 4/6），而旧基线上 salted 是零。但饥饿没修好：驻留中位只有 328 个
token，理论上限 2112；而且有意思的是，它的形态变了——从旧版的'静默撤销'变成了
计数器可见的分配失败，host_capacity 原因的未履约一次涨一万四。我加了一个 4 倍
容量的剂量臂想证伪，结果饥饿消失了但机制变形了：单线程的 L3 写管线被放大 2.7 倍
的写入压垮，读查询在超时预算内挤不过去就被静默切断——零计数、零日志、重试一并
取消，对外伪装成 miss。我顺着 TTFT 聚类和'盘上文件数精确等于 ack 数'证伪了数据
丢失假说，定位到批查询接口——这是 IO 管线的结构问题，不是容量问题。同一套负载我复现了上游 issue #49221：
并发 16 时命中跌到串行的 28%，未履约里 96% 是 admission shortfall，buffer_only
模式完全免疫、池放大 4 倍完全恢复——机制归属闭环。这些证据直接支撑了上游
正在进行的修复 PR，也暴露了它覆盖不到的部分。"（若面试官追问修复参与：
如实说明证据贡献 + 后续 #36280 观测性补丁路线）

**结局 B（实验 0 验证已修复）**：
"双臂验证的结果是 main 的修复是完整的：〔槽位：两臂同命中、三类 unfulfilled 均
低于阈值、剂量臂边界〕。这本身是有价值的负结果修正——我把验证方法沉淀成了
可复现的实验包，顺手补上了这个链路的观测缺口：prefetch 撤销事件的指标导出，
上游维护者点名过这个需求，补丁已经做好待投。"
